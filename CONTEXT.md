# CONTEXT — Unkillable domain glossary

The site at unkillable.bitcoin-fix.com lets a completely non-technical visitor attempt famous attacks on Bitcoin and watch the network survive. These are the project's terms; use them everywhere — code, plans, issues, commits.

- **Attack** — one of the seven famous doubts a visitor can act on (hack, shut down, 51%, ban, print, time, quantum). One page each.
- **Tool** — the single interactive visual that IS an attack page. The tool is the teacher: text exists only as labels and one-line reactions, never narration.
- **Engine** — an attack's pure-logic brains layer (TypeScript, no visuals): actions in, reactions out. The tested surface.
- **Turn** — one visitor action and the tool's reaction to it.
- **Scar** — the live record stat on a weapon card in the armoury ("0 keys ever guessed"; quantum reads "Pending.").
- **Stamp** — the FAILED mark a completed attack leaves on its hub card, remembered in the visitor's browser.
- **Footnote** — an attack's single collapsed honest-disclosure line that expands on tap.
- **Data tap** — the one shared module answering "what does the network look like right now": live source first (mempool.space, Bitnodes), bundled snapshot fallback, always exposing which mode it's in and the data's date. Pages never call live sources directly.
- **Observatory** — the homepage: the live globe, the blockchain strip with its ~10-minute countdown, one orange button.
- **Armoury** — the attack-selection hub of seven weapon cards.
- **Report card** — the journey's ending: six ❌ FAILED, quantum ⏳ PENDING, shareable.
- **Fundamentals** — the eight-card explainer ladder, ordered for the everyday layman; cards also open as mid-attack overlays.
